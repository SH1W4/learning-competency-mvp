## Objective

Choose one organizational context and one competency that can be taken through the complete MVP flow.

## Tasks

### M1.1 — Select organizational context
Owner: TBD
Dependency: none
Deliverable: one chosen context/program.
Done when: context, problem owner and learner are named in docs/product/USE_CASE.md.

### M1.2 — Define competency
Owner: TBD
Dependency: M1.1
Deliverable: operational competency definition.
Done when: capability, observable outputs/behaviors, evidence expectations and review criteria are explicit.

### M1.3 — Design short trail
Owner: TBD
Dependency: M1.2
Deliverable: 2–5 activities that intentionally generate evidence.
Done when: every activity has objective, action, output, evidence and competency relation.

### M1.4 — Define evidence contract
Owner: TBD
Dependency: M1.3
Deliverable: limited evidence types and required metadata.
Done when: each evidence type has source, provenance, activity link and expected interpretation.

### M1.5 — Define minimal competency states
Owner: TBD
Dependency: M1.2 + M1.4
Deliverable: bounded state vocabulary for the demo.
Done when: the team can explain what causes each state transition without relying on an opaque AI judgment.

### M1.6 — Freeze demo scenario
Owner: TBD
Dependency: M1.1–M1.5
Deliverable: canonical synthetic/demo scenario.
Done when: the complete scenario is documented and reproducible without inventing user results or traction.

## Exit criteria

organization → competency → trail → person → activity → evidence is fully specified and ready for implementation.
